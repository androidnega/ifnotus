## 1. Executive conclusion

IFNOTUS is a real, working Ghana-focused hosting *product* (billing, portal,
tenant panel, student hostnames, nginx provisioning) running on a single
powerful VPS. It is NOT yet a clean ISPConfig-backed production hosting engine.

Current truth:
  - Public HTTP(S) = nginx (active)
  - All 7 customer environments = provider=legacy
  - ISPConfig = NOT installed
  - ISPConfig adapter = CODE ONLY (not wired into ProvisioningEngine)
  - OLSPanel/OpenLiteSpeed = leftover install (stopped/disabled; dirs remain)
  - Product apps (VoteBridge, QuizSnap, ExamFlow, …) share the same VPS

GO / NO-GO: LIMITED BETA ONLY for carefully selected customers.
Not ready for unrestricted public business hosting until ISPConfig cutover,
firewall cleanup, resource isolation hardening, DNS redundancy, and offsite
backups are completed.

Highest priority fix themes:
  1) Firewall surface left open by OLS attempt (3306/6379/7080/4958/19999…)
  2) Wire HostingProvider into provisioning OR stay legacy consciously
  3) Make resource limits REAL (OS quotas + cgroups), not mostly display/app
  4) Separate product apps from tenant hosting operationally
  5) Offsite backups + restore drills

* Staff use platform routes; may also hit customer portal if customer row exists.
† Admin FILES/DB write intentionally restricted in role matrix comments.
‡ Operator has FILES_WRITE host-wide by design (WHM-like).

Risks:
  - Staff files/DB APIs are host-wide (by design) — any compromised staff token
    with write perms is cross-tenant capable.
  - DenyCustomerHost protects /hosting aggregate routes from pure customers.
  - Tenant portal uses get_owned_environment — good IDOR baseline.
  - _require_customer_user allows admin/superadmin into portal APIs — prefer
    staff platform routes only.
  - ISPConfig credentials must NEVER be customer-facing.

Recommended hierarchy (keep/refine existing):
  SUPER ADMIN → platform + infra + terminate + ISPConfig remoting secrets
  ADMIN/STAFF → customer ops without root shell
  CUSTOMER → own account only
  SERVER ENGINE → ISPConfig/OS never exposed as customer credentials
