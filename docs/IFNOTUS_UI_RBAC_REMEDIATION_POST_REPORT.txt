1. EXECUTIVE CONCLUSION
----------------------------------------------------------------------------------------------------
The IFNOTUS UI RBAC Remediation has been fully implemented across all canonical roles (`platform_owner`, `platform_admin`, `hosting_operator`, `billing_agent`, `support_agent`, `auditor`, and `customer`).

Every role now sees ONLY the pages, navigation menus, dashboard cards, tabs, and action-level buttons aligned strictly with their backend authorization privileges. Backend authorization remains authoritative, and frontend UI visibility exactly matches the IAM security boundaries without loosening security or relying on cosmetic hiding.

Key Accomplishments:
1. Permission Constants Alignment: Added `billing:view`, `billing:manage`, `disaster_recovery:execute`, and `providers:manage` across backend (`app.core.permissions`) and frontend (`lib/permissions.ts` and `lib/uiRegistry.ts`).
2. Support Agent Financial Leak Plugged: `platform_admin.py` orders and accounting endpoints now require `Permission.BILLING_VIEW` / `Permission.BILLING_MANAGE` rather than generic `CUSTOMERS_MANAGE`. `support_agent` has 0 access to financial orders, ledgers, and payment confirmations.
3. Role-Partitioned Staff Sidebar: Completely rebuilt `frontend/src/components/layout/AppSidebar.vue` with dedicated computed navigation structures per canonical role. Emergency Web Terminal is visually isolated and strictly restricted to `platform_owner`.
4. Router Guard Hardening: `frontend/src/router/index.ts` guards every staff route by permission and canonical role boundary, denying unauthorized URL navigations.
5. Action-Level Button Gating: Mutation controls in `PlatformCustomersView.vue`, `PlatformOrdersView.vue`, `SecurityView.vue`, and `OperationsView.vue` are individually gated by role and permission. Destructive actions (`Delete Customer`, `Terminate Environment`) are restricted strictly to `platform_owner`.
6. Platform Admin Infrastructure Pollution Removed: Cleaned all raw server, host filesystem, terminal, and daemon views from `platform_admin`.
7. Customer Plan Entitlement Tab Gating: `HostingPanelView.vue` and `PortalSitePanel.vue` dynamically evaluate `envCan(...)` and hide zero-entitlement tabs (Mail, Databases, Cron, SFTP, Applications) rather than rendering dead forms.
8. Settings Tab Partitioning: `SettingsView.vue` isolates AI keys, provider integrations, and staff management to `platform_owner`, theme/webmail to `platform_owner` + `platform_admin`, and keeps general profile for all staff.
9. Split Applications View: Added dedicated Platform Products section (`VoteBridge`, `QuizSnap`, `ExamFlow`) for `platform_owner` while separating Hosted Tenant Applications.
10. Test Suites & Production Build: 417/417 backend pytest tests pass; frontend `vue-tsc -b && vite build` passed cleanly with 0 TypeScript errors.

  - `billing_agent` blocked from host infrastructure and raw tech tools.
  - `support_agent` blocked from financial orders, accounting, plans, and server tools.
  - `auditor` blocked from `/terminal`, `/files`, and mutation routes.
  - Non-owners blocked from raw host filesystem `/files` and emergency `/terminal`.
