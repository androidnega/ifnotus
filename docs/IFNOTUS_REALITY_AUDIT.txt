ISSUE 1
SEVERITY: P0
FILE: Live DNS / registrar configuration (code: docs/phase23 + deploy/dns; live NS)
FUNCTION / CLASS: N/A (infrastructure)
PROBLEM: Public NS for serverlabsttu.space are dns1/dns2.registrar-servers.com.
         Local BIND has correct wildcard zone, but the internet does not use it.
         dig @1.1.1.1 A testaudit.serverlabsttu.space → NXDOMAIN.
WHY IT MATTERS: New student sites will not resolve for the public. SSL issuance for
         those hostnames will fail. Product promise for student hosting is broken live.
RECOMMENDED FIX: At registrar, set NS to ns1.ifnotus.space / ns2.ifnotus.space
         (already A→80.241.223.82). Verify dig NS + wildcard A via 1.1.1.1.
         Do NOT claim student hosting production-ready until this passes.

------------------------------------------------------------------------
ISSUE 2
SEVERITY: P0
FILE: backend/app/services/platform/env_cron.py
FUNCTION / CLASS: EnvironmentCronService._build_argv
PROBLEM: Docstring says never as root; if unix_username empty, returns bare
         bash -lc under worker. Live ifnotus-worker.service User=root.
WHY IT MATTERS: Cron can execute as root on the Contabo host.
RECOMMENDED FIX: Hard-fail if unix_username missing or runuser/sudo -u fails.
         Never fall back to worker identity. Prefer dedicated non-root worker UID.

------------------------------------------------------------------------
ISSUE 3
SEVERITY: P0
FILE: Live /etc/ssh/sshd_config.d/ (missing ifnotus-sftp.conf);
      backend/app/services/platform/sftp_access.py
FUNCTION / CLASS: EnvironmentSftpService (sshd drop-in writer)
PROBLEM: Phase-19 Real SFTP config is not present on the live sshd drop-in set.
         ifn_* user count = 0. Existing access is FTP (vsftpd) + SSH group ifnotus-ssh
         without ChrootDirectory.
WHY IT MATTERS: Marketing/docs claiming Real SFTP DONE are overstated for live.
         Interactive SSH users are not SFTP-chrooted.
RECOMMENDED FIX: Ensure ensure_account path runs and reloads sshd; create ifn_* at
         provision; verify Match Group ifnotus-sftp + ChrootDirectory live.
         Keep FTP labelled FTP until SFTP is verified.

------------------------------------------------------------------------
ISSUE 4
SEVERITY: P0
FILE: backend/app/services/platform/ssh_access.py + ftp.py
FUNCTION / CLASS: EnvironmentSshService.ensure_access / sync_from_environment
PROBLEM: SSH password is applied via chpasswd to the FTP OS user (u*). Separate
         ciphertext fields do not create separate OS passwords.
WHY IT MATTERS: “SSH password separate from FTP” is false at OS layer once SSH enabled.
RECOMMENDED FIX: Dedicated OS identity for SSH or never share FTP account; stop
         overwriting FTP passwd; panel must reflect OS truth.

------------------------------------------------------------------------
ISSUE 5
SEVERITY: P0
FILE: backend/app/services/platform/billing.py
FUNCTION / CLASS: _suspend_environments / _terminate_environments
PROBLEM: Sets DB status (and stop_container on terminate) but does NOT call
         EnvironmentLifecycleService (no unix lock, no SFTP/FTP disable, no nginx off,
         no userdel).
WHY IT MATTERS: Non-renewal “terminate” leaves live OS credentials and possibly
         web serving until something else cleans up.
RECOMMENDED FIX: Delegate to lifecycle.suspend / lifecycle.terminate.

------------------------------------------------------------------------
ISSUE 6
SEVERITY: P1
FILE: Live filesystem + environment_storage.py
FUNCTION / CLASS: apply_os_user_quota
PROBLEM: os_user_quota_enabled=True but setquota/quotaon not installed; mount
         options lack usrquota. Quotas cannot apply.
WHY IT MATTERS: Disk limits are app/API soft checks; SFTP/FTP/direct writes can
         bypass panel assert_write_allowed.
RECOMMENDED FIX: Install quota tools; remount with usrquota (or project quotas);
         verify setquota -u for ifn_* users; alert if applied=False.

------------------------------------------------------------------------
ISSUE 7
SEVERITY: P1
FILE: backend/app/services/hosting/databases.py
FUNCTION / CLASS: DatabaseManagerService.create (MySQL grants)
PROBLEM: Grants MySQL user@'%' even when entitlement remote_access_mode is localhost.
WHY IT MATTERS: Unexpected remote DB exposure if MySQL listens beyond localhost.
RECOMMENDED FIX: Grant @'localhost' unless remote entitlement true; bind MySQL
         appropriately; firewall.

------------------------------------------------------------------------
ISSUE 8
SEVERITY: P1
FILE: backend/app/services/hosting/db_studio.py
FUNCTION / CLASS: _run_query (is_write_sql unused)
PROBLEM: Staff SQL studio executes arbitrary SQL including writes/DDL.
WHY IT MATTERS: Privilege blast radius for staff accounts with databases:write.
RECOMMENDED FIX: Enforce is_write_sql / role gates; default read-only studio.

------------------------------------------------------------------------
ISSUE 9
SEVERITY: P1
FILE: backend/app/services/platform/application_runtime.py
FUNCTION / CLASS: Node stub / _allocate_port
PROBLEM: Stub may listen on PORT||3000 without supervisor injecting allocated_port;
         port allocator only uniqueness-checked within one environment.
WHY IT MATTERS: Broken apps / cross-env port collisions under load.
RECOMMENDED FIX: Always inject PORT; allocate from global used-port registry.

------------------------------------------------------------------------
ISSUE 10
SEVERITY: P2
FILE: Live customer docroots under /srv/apps/ifnotus-customers
FUNCTION / CLASS: fs_ownership / nginx serving
PROBLEM: Observed ownership www-data:www-data and permissive modes; parent dirs root-readable.
WHY IT MATTERS: Weak DAC; SSH-entitled users without chroot may read other tenants.
RECOMMENDED FIX: Per-tenant uid ownership; remove world-read; chroot SSH or disable
         interactive SSH on shared node until jailed.

   then port collisions / noisy neighbors without hard cgroup/quota isolation.

5. What can currently bring down the whole server?
   - Cron/jobs as root worker compromise or runaway cron
   - Disk fill without OS quotas
   - Cross-tenant SSH read + abuse
   - Unbounded remote MySQL grants if mysqld exposed
