3. COMPONENT IMPLEMENTATION DETAILS
================================================================================

A. BACKEND ARCHITECTURE (FastAPI & Services)
--------------------------------------------
1. Single-Use SSO Token Service (`backend/app/services/platform/sso.py`):
   - Generates signed JWT handoff tokens with 120-second TTL and unique JTI (UUIDv4).
   - Atomic consumption via Redis `SET ... EX 240 NX` with in-memory lock fallback.
   - Host mismatch validation ensures token can only be consumed on the intended tenant domain.
   - Mints standard access/refresh token pair for tenant cPanel session upon successful exchange.

2. Panel Access & URL Formatting (`backend/app/services/platform/panel_access.py`):
   - `control_panel_hostname(domain)`: Canonical `cpanel.<domain>` (or `cpanel.<primary>` for subdomains).
   - `webmail_hostname(domain)`: Canonical `webmail.<domain>`.
   - `site_cpanel_url(domain, tab)`: `https://cpanel.<domain>/<tab>` (e.g. `https://cpanel.domain.com/files`).
   - `site_cpanel_shortcut_url(domain)`: `https://<domain>/cpanel`.
   - `site_webmail_url(domain)`: `https://webmail.<domain>`.
   - `site_mail_url(domain)`: `https://webmail.<domain>`.

3. Authoritative DNS Provisioning (`backend/app/services/platform/authoritative_dns.py`):
   - Automatically populates BIND9 zone templates with:
     - `IN NS ns1.ifnotus.space.`
     - `IN NS ns2.ifnotus.space.`
     - `@ IN A <ipv4>`
     - `www IN A <ipv4>`
     - `cpanel IN A <ipv4>`
     - `webmail IN A <ipv4>`
     - `mail IN A <ipv4>`
     - `@ IN MX 10 mail.<domain>.`
     - `@ IN TXT "v=spf1 mx a:mail.<domain> ~all"`
     - `default._domainkey IN TXT ...` (DKIM)
     - `_dmarc IN TXT "v=DMARC1; p=none; sp=none; aspf=r; adkim=r;"`

4. Multi-SAN SSL Provisioning (`backend/app/services/hosting/ssl.py`):
   - `_issue_domain_names` generates certificates containing:
     - `<domain>`
     - `www.<domain>`
     - `cpanel.<domain>`
     - `webmail.<domain>`
     - `mail.<domain>`

5. Nginx VHost Provisioning (`backend/app/services/hosting/nginx_provisioner.py`):
   - Renders HTTPS server blocks for `cpanel.<domain>` serving customer Vue SPA.
   - Renders HTTPS server blocks for `webmail.<domain>` proxying to Roundcube.
   - Renders HTTPS server blocks for `mail.<domain>` redirecting to `https://webmail.<domain>`.
   - Renders apex domain redirects:
     - `location = /cpanel { return 302 https://cpanel.$host$request_uri; }`
     - `location = /webmail { return 302 https://webmail.$host$request_uri; }`
     - `location = /mail { return 302 https://webmail.$host$request_uri; }`


B. FRONTEND ARCHITECTURE (Vue 3, TypeScript & Vue Router)
---------------------------------------------------------
1. Host-Based Tenant Detection (`frontend/src/lib/platformHosts.ts`):
   - `isCustomerCpanelHost()` detects `cpanel.<customer-domain>`.
   - `tenantCpanelUrl()` builds canonical `https://cpanel.<domain>/<tab>` URLs.
   - `openTenantCpanel()` invokes SSO handoff API (`POST /api/v1/customers/sso-handoff`) to seamlessly transition customers to `https://cpanel.<domain>/sso?token=...`.

2. SSO Landing Component (`frontend/src/views/portal/SsoLandingView.vue`):
   - Consumes single-use token on tenant origin via `POST /api/v1/public/sso/consume`.
   - Stores session tokens and tenant environment context in localStorage.
   - Redirects to root `/` or specified clean subroute (`/files`, `/databases`, etc.).

3. Clean URL Routing (`frontend/src/router/index.ts`):
   - Added clean named routes on customer cPanel domain:
     - `/` -> Overview
     - `/files` -> File Manager
     - `/databases` -> Databases
     - `/domains` -> Domains
     - `/email` -> Email Management
     - `/apps` -> Application Installer
     - `/cron` -> Cron Jobs
     - `/backups` -> Backups
     - `/logs` -> Logs & Metrics
     - `/usage` -> Resource Usage
     - `/transfer` -> Site Migration
   - Completely removes `/hosting/:environmentId` exposure from customer-facing navigation.

4. UI Onboarding Copy Update (`frontend/src/components/portal/PortalSitePanel.vue`):
   - Nameserver delegation promoted as Primary / Recommended method (`ns1.ifnotus.space`, `ns2.ifnotus.space`).
   - Raw server IP removed from default setup flow and relegated strictly to "External DNS Mode (Manual Records)".
