================================================================================
IFNOTUS FILE MANAGER — TRASH / RECYCLE BIN FEATURE IMPLEMENTATION REPORT
================================================================================

1. TRASH ARCHITECTURE
- Normal delete operations from the Customer File Manager perform a non-destructive soft delete into a tenant-private Trash container.
- Physical storage is strictly isolated outside the public web document root (placed in `<tenant root>/.ifnotus-trash/` or `<docroot>/.ifnotus/trash`).
- Stored items are uniquely named using `<trash_id>__<clean_filename>` to avoid collisions on multiple deletions of files with the same name.
- Restore metadata (UUID, original relative path, stored name, item type, size in bytes, deletion timestamp, deleted by actor) is atomically persisted in `manifest.json`.
- The customer UI interfaces with a virtual `Trash` location under PLACES in the sidebar.

2. PHYSICAL TRASH LOCATION
- Provider-agnostic location:
  - If document root is `public_html` / `web` / `httpdocs` and parent is accessible: `<environment_root>/.ifnotus-trash/`
  - Fallback: `<docroot>/.ifnotus/trash/`
- Directory permissions are secured at `0700` and owned by tenant UID/GID.

3. METADATA / DATABASE CHANGES
- `CustomerTrashEntrySchema` / `TrashEntrySchema` with fields: `trash_id`, `original_path`, `display_name`, `item_type`, `size_bytes`, `deleted_at`, `deleted_by`.
- Atomic manifest file `manifest.json` stored inside the environment's trash root, ensuring cross-platform and provider portability without brittle schema dependencies.

4. NORMAL DELETE BEHAVIOR
- Selecting an item or multiple items in the File Manager and clicking "Delete" prompts `Move "<name>" to Trash?` / `Move N items to Trash?`.
- Upon confirmation, calls `POST /customers/environments/{id}/files/trash` or `DELETE /customers/environments/{id}/files?permanent=false`.
- A success flash banner appears with an interactive `Undo` button.

5. TRASH LISTING
- Virtual location `Trash` displays columns: Name, Original Location, Deleted (relative/formatted date), Size, and Type.
- Filter and search support searching by display name or original location.
- Empty state renders `IconTrash` with "Trash is empty" and "Deleted files and folders will appear here."

6. RESTORE BEHAVIOR
- Selecting one or more items in Trash and clicking `Restore` moves items back to their `original_path`.
- Path resolution uses `_safe_path` sandboxing to prevent any escaping or traversal.
- Successful restoration shows `Restored "<name>"` and clears the item from Trash.

7. RESTORE CONFLICT BEHAVIOR
- If an item with the same name already exists in the destination folder:
  - Backend supports conflict modes: `copy`, `replace`, `cancel`.
  - Frontend prompts a resolution modal: "Restore as copy", "Replace existing", or "Cancel".
  - "Restore as copy" generates `name (restored).ext` or `name (restored N).ext` without data loss.

8. PERMANENT-DELETE BEHAVIOR
- Available exclusively within the `Trash` location.
- Confirmation: `Permanently delete "<name>"? This cannot be undone.`
- Removes the physical file/directory from disk and purges the manifest entry.

9. EMPTY-TRASH BEHAVIOR
- "Empty Trash" button in Trash toolbar purges all trashed files/directories for the active environment only.
- Scoped strictly to the authenticated tenant environment.

10. QUOTA BEHAVIOR
- Trash files reside within the tenant's filesystem container and quota root, correctly counting toward allocated disk usage until permanently deleted or emptied.

11. SECURITY / TENANT ISOLATION
- Strict document root jailing via `_safe_path`.
- Cross-tenant IDOR protection: Trash IDs are scoped strictly to the authenticated environment and validated against the tenant's private manifest.
- Symlinks are moved/unlinked directly without escaping the jail boundary.

12. AUDIT LOGGING
- All operations log to `PlatformAuditLog` with customer ID, actor user ID, environment ID, and metadata:
  - `file_moved_to_trash`
  - `file_restored`
  - `file_permanently_deleted`
  - `trash_emptied`
